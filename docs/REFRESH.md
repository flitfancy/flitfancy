# 页面刷新调度与后端统一心跳

`assets/refresh-scheduler.js` 统一管理周期性的数据读取。控制台、存在页和旅途日记各有一个页面调度器；模块保留各自的请求和展示职责，不再各写一组轮询计时器。这个共享组件并不使浏览器标签页共享内存或登录状态。

后端 `flitfancy_refresh.py` 在同一进程内集中记录实际读取结果。数据接口通过原有鉴权后，读取和响应的同一条处理路径顺手更新心跳，控制台从私有 `/api/refresh/status` 获取汇总。存在页不再承担心跳转发，页面关闭也不会抹掉后端已有记录。

## 刷新安排

| 任务 | 正常间隔 | 页面在后台 |
| --- | --- | --- |
| 服务状态、现实感知 | 5 秒 | 暂停 |
| 全界之桥状态 | 5 秒；传输进行时由原传输流程更新 | 暂停状态轮询，传输流程保持原行为 |
| 本机启动 | 空闲 5 秒，等待执行/选择时 2 秒 | 暂停 |
| 音频状态 | 活跃约 0.6 秒，空闲约 2.5 秒，未连接约 4 秒起退避 | 放慢到至少 15 秒 |
| 音频历史 | 展开时 15 秒 | 暂停 |
| 电脑使用 | 10 秒 | 暂停页面读取，后台 AW 采集和归档继续 |
| 感知历史 | 展开时 60 秒 | 暂停 |
| 公开对话配置 | 60 秒 | 暂停 |
| 旅途日记 | 10 秒，保存后请求新结果 | 暂停 |
| 控制台心跳记录 | 5 秒，只读后端内存汇总 | 暂停 |

同一任务最多一个读取请求在途；周期刷新不堆积。用户切换日期、通道等参数时最多合并一个后续刷新。控制台/存在页最多同时运行三个读取任务。普通失败指数退避到最多 60 秒，成功恢复正常频率；401 等待重新登录。重新联网、回到前台或登录后及时协调任务。浏览器前进后退缓存恢复也会重新协调，而非启动第二组计时器。

AW 后端采集、数据库归档、公开数据同步、文件分块传输、动画、输入防抖和下载链接清理均有各自职责，不受页面刷新计时器的启停控制。

## 心跳代表什么

控制台的“刷新心跳”只在登录后显示。一个成功光点代表对应的数据接口在网站后端完成了成功响应，不代表前端已经渲染、NAS/音频设备在线或后台采集健康；这些能力的实际状态继续在各自模块内显示。只有新完成记录才触发光点，首次打开面板不把历史记录装成新刷新。

面板默认只显示上方圆点和下方名称，成功读取时闪动，失败时圆点和名称标红，尚未发生的读取置灰。点击一项会像感知卡片一样原位进入详情，显示最近成功时间、最近读取结果、后端处理耗时、完成次数、连续失败次数和正在处理数；点“返回”或按 Escape 回到圆点列表。无悬停提示，查看详情也不会触发额外业务读取。后端不知道页面何时发起下一次请求，所以不虚构倒计时。手动更新只更新这份记录，不再触发每个业务接口重新取数。

统一记录当前涵盖服务状态、现实感知、感知历史、音频状态、音频历史、电脑使用、全界之桥状态、本机启动和本地日记读取。仅匹配固定 GET 路径，不记录 query、文件名、对话、窗口标题、请求体、凭证、IP 或任意错误详情。未通过鉴权的请求不污染记录。上传、下载和写入流程不纳入此读取统计。

这是网站 Python 后端的读取记录。公网 `api.flitfancy.com` 的 Cloudflare Worker 是另一套服务，公开旅途日记等云端请求不混入本地记录。本机允许匿名的公开读取仍遵循已有精确例外；汇总接口在本机和隧道下都必须管理员登录。

所有心跳记录只存在于后端进程内存，不新增数据库表，不做长期归档。多线程读取通过锁保护计数；状态查询自身不计入心跳，避免自我制造活动。后端重启会清空记录并提供新的启动标识，面板据此重置动画基线。升级到此版需要重启网页后端一次。

列表保留稳定的节点，不因数据更新抢走键盘焦点，动画遵循减少动态效果偏好。查询失败时明确提示记录没有更新，而不把所有业务项目改成失败；401 清除私有显示，404 提示旧后端需要重启。心跳展示不使用 `BroadcastChannel`，也不依赖其他标签页登录或保持打开。

## 新模块接入

通过页面传入的 `opts.scheduler.register({id,label,page,interval,enabled,requiresAuth,hidden,run})` 登记，`run` 只负责一次真实读取。成功返回 `{ok:true}`，失败返回 `{ok:false,status}` 或抛错，无需读取时返回 `{skipped:true}`。跳过不会制造成功心跳。错误元信息只保留状态码对应的固定类别。

手动入口使用返回句柄的 `refresh()`；参数变化需要合并后续读取时用 `refresh({rerun:true})`。模块仍必须校验自己的登录/参数版本，防止迟到结果重新显示旧内容。不要从 `run` 中等待同一个任务的 `refresh()`，避免自我等待。模块关闭调用 `unregister()`，整页离开调用 `dispose()`。

新读取接口若需要进入后端心跳，在 `flitfancy_refresh.py` 的固定路径目录和 `console-heartbeat.js` 的展示目录登记，并补充对应鉴权、失败与并发测试。不要把用户内容当作任务名称或错误原因，也不要为显示心跳额外执行一次业务读取。
