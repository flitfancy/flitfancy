# 模型网关与咨询接口

小流萤继续由 AstrBot 和本地模型负责对话；需要时，咨询插件通过本机网站后端与 Cloudflare Worker 调用所选云模型。网页的“模型直聊”使用同一套云端模型配置，但有独立的消息历史。两条路径都不改变原有小流萤人格与本地模型选择。

## 当前边界

- 云模型服务商、模型名称、接口地址和网页开放范围在控制台选择。模型 API 密钥仅写入对应 Worker 加密变量；本机仍需已有的 Worker 管理连接凭据。
- 管理员可在当前 OpenAI 配置已就绪且旧访客聊天关闭后清理旧模型密钥及其配置；清理保留 OpenAI、Cloudflare 管理令牌和所有聊天历史。旧模型日后需要重新输入密钥。
- 小流萤咨询仅供主人的私聊会话使用。实际提问、模型原答或失败状态保存在本机咨询记录，只有管理员可读取。
- 网页直聊可关闭、仅管理员或开放访客，默认仅管理员。管理员直聊历史保存在本机网站数据库，是现有管理员角色共同可访问的管理空间；访客历史保存在自己的浏览器。两者不读取小流萤的私聊与咨询记录。
- 新会话不带其他会话历史；打开旧会话时继续该会话。管理员每次请求由本机选取最近完整问答，访客由浏览器选取，均有限制长度。记录保留与上游提示缓存是不同的能力。
- 模型直聊可在输入处选择已配置服务和模型；同一服务切换模型沿用当前会话，跨服务切换时须选择携带近期上下文或从当前消息重新开始。重新开始只改变之后发送的上下文，旧消息仍可查看。现有历史通过追加字段迁移，访客记录仍在自己的浏览器。
- 每个服务可配置一个默认模型和最多 19 个其他模型；除 OpenAI、DeepSeek 和 MiMo 外，还提供三个独立的 Chat Completions 兼容接口。模型临时选择不会更改小流萤咨询的默认服务。只有管理员明确开放给访客的服务才出现在访客模型列表中；升级前已开放的旧配置默认仅公开原模型，不会自动把新推荐模型开放给访客。
- 思考强度按服务和模型实际支持的参数提供；未知兼容接口只提供自动模式。配置保存不代表连接一定成功，密钥仅显示已保存状态，不回显原文。
- Cloudflare 网关从启用统计后尽力记录调用来源、模型、强度、状态和服务返回的 token 数，不保存提示词、答复或密钥；网关或数据库异常时可能遗漏。OpenAI `gpt-6.1-sol` 标准档且计费明细完整时按 2026-11-08 价格估算，其余标为无法估算；未知用量不视为零。官方账单、余额和赠额度仍以服务商为准。
- 小流萤网页的新建与切换操作使用 AstrBot 同一个会话指针，QQ 与板子也跟随；网页展示该会话最近 40 条，完整历史仍由 AstrBot 保存。
- 本地优先；明确要求只用本地时不咨询云端。自动预判基于关键词，不能保证识别所有复杂问题或所有自然语言表述。
- 常见凭据格式出现在本轮消息、实际选取的相关上下文或咨询问题时，咨询会停止，不写入咨询记录。规则无法识别所有可能的密钥，仍不要在对话中输入凭据。
- 模型响应失败时不会自动重试；网页保留输入供人工确认。网络超时不能证明上游一定没有处理请求。

## 已有接口

| 调用方 | 接口 | 用途 |
| --- | --- | --- |
| 管理网页 | `GET /api/model-gateway/status` | 获取当前或指定服务的状态、接口版本与能力。 |
| 管理网页 | `GET /api/model-gateway/catalog`、`GET /api/model-gateway/usage` | 获取已配置模型列表及本站用量摘要。 |
| 管理网页 | `POST /api/model-gateway/config` | 保存所选模型、访问范围及可选的新模型密钥。 |
| 管理网页 | `POST /api/model-gateway/chat` | 独立模型对话。 |
| 管理网页 | `GET/POST /api/model-gateway/conversations` | 分页列出或创建本机模型直聊会话。 |
| 管理网页 | `GET /api/model-gateway/conversations/{id}` | 分页读取某个会话的消息。 |
| 管理网页 | `POST /api/model-gateway/conversations/{id}/turns` | 保存本轮并发送该会话的近期上下文；请求编号用于去重。 |
| 管理网页 | `POST /api/model-gateway/cloudflare-token` | 首次提交范围受限的 Cloudflare 管理令牌。 |
| 管理网页 | `GET /api/consultations?after=...` | 按游标读取本机私有咨询事件。 |
| 公开网页 | `GET /gpt/status`、`POST /gpt/chat` | 仅在访客开放时使用的独立对话。 |

本机 `/api/` 管理接口沿用已有管理员会话与跨站请求防护。Worker 的 `/admin/model/status`、`/admin/model/config`、`/admin/model/chat` 和 `/admin/model/cleanup-old` 是管理服务端接口，不是第三方客户端的登录接口。不要把 Worker 管理令牌交给外部框架。清理旧密钥后，原 `/chat` 访客入口不能继续使用，开放访客模型聊天应使用新的 `/gpt/chat` 入口。

管理状态的 `interface_version` 为 `1`；`capabilities` 声明当前支持 `text`、`multi_turn`，不支持网关级 `streaming`、`tools` 或 `images`。模型直聊消息为 `user` / `assistant` 文本，携带所选服务、模型、思考强度及 `profile_id`，以防配置变更后把旧会话发给意外的服务。会话的失败或重启中断状态会保留，但不会自动加入下一轮上下文或自动重发。服务端咨询用途为 `consult`，独立直聊用途为 `chat`；结果包含实际模型、服务、答复和可用的用量信息。

小流萤插件接受事件级 `firefly_model_policy=local_only`，该标记优先于自动判断和工具调用。当前网页和语音通道尚未提供这个结构化字段的透传入口；现有自然语言规则是辅助，不应当作覆盖所有表述的安全开关。

## 为其他框架预留

目前 `/gpt/chat` 与 `/admin/model/chat` 是站点自用的文本接口，并非 OpenAI 标准 API。将来若接 DeepSeek Harness 等框架，需要新增独立的标准协议适配、范围受限且可撤销的客户端凭据，并按目标框架实际需求实现和验证流式、工具调用、模型发现等能力；不能只改 URL 或复用管理员令牌。
